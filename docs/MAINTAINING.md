# 处理反馈和贡献

普通玩家在工坊页面留言反馈，中英文都可以，不需要 GitHub，也不需要知道地点的内部 ID。GitHub 上的问题模板和 PR 留给愿意直接改源码的人。

## 处理一条正文纠错

1. 先认准地点。玩家给的地名、地区或截图可以用 `tools/find_location.py` 查候选；同名地点要在研究库里按坐标核对。
2. 核对资料是否真的支持这个说法。可靠的非维基资料可以作为依据。
3. 在研究库里修改。PR 里的正文只当提案，不直接改 `data/` 或生成的本地化文件。
4. 中英文一起改，两种语言讲的事实要一致。只给了一种语言的修改，要补齐另一种再发布。
5. 从研究库重新导出整份数据，确认只有预期的地点发生变化。
6. 按 [PUBLISHING.md](PUBLISHING.md) 发版；`CHANGELOG.md` 里写明改了什么。贡献者愿意署名的，在更新说明里写上。

## 发布证据（可选）

`tools/preflight.py --evidence <json> --require-publish-ready` 可以检查一份人工验收记录：复制 [release-evidence.example.json](release-evidence.example.json)，填入实际包的 SHA-256、版本、游戏 build 和工坊 ID，每个通过项都引用证据目录里的记录或截图及其 SHA-256。工具只核对记录和包是否对应、文件是否被改动，不判断截图内容是否真实，也不代表可以发布。
