# 更新与回滚

每次发布记录源版本或Git commit、模组版本、Steam build、ZIP/文件清单哈希、工坊条目ID和实际验收结果。当前没有工坊条目ID，不填虚构值；GitHub目标为私有仓库 `wangyufeng0615/eu5-location-descriptions`，游戏与工坊验收完成前保持私有。

## 正常更新

正文修改在研究工程完成，从确认过的完整正文检查点单向导入；当前研究库没有独立冻结数据库，导出按只读事务取得一致内容。发布工程维护元数据、包装文档和素材。更新 `project.json` 版本及双语变更说明，构建到新的 `dist/` 目录，执行 `--verify`、预检和必要的游戏验收。不要覆盖旧的已验收产物。

游戏补丁更新后重新核对地图目标、官方新增介绍和7份源指纹。新增官方介绍必须从模组目标中保护出去，不能仅修改 `supported_game_version`。构建失败或源基线不符时停止发布。

在游戏Mod Tools中选择已上传条目，用“Upload content from a folder”更新同一个ID。检查实际账号、内容文件夹、页面语言与可见性，不每次创建新条目。Steam可能对更新进行审核，订阅者在审核期间可能仍收到旧版；通过真实下载与版本哈希判断结果。

## 回滚

保留上一份已验收ZIP及对应源码/回执。将它解压到新的空目录，核对包内容和游戏基线，再向同一个工坊ID上传旧的良好内容，并写明回滚原因和目标版本。不要删工坊条目重建，以免丢失订阅及讨论。不要直接删除或覆盖正在使用的本地目录。

如果旧包不适配当前游戏补丁，回滚不能替代修复。先收敛错误、重新构建和验收，必要时在工坊页面说明已知问题。

## 上传问题

核对Steam运行和联网、账号提交资格、条款接受、注册邮箱确认、平台审核状态，再核对内容路径。查看Steam `logs/Workshop_log.txt` 与 `workshopbuilds/depot_build_3450310.log`（是否实际生成取决于上传途径）。保留有关错误码和时间，不记录密码、Guard码或完整个人路径。不要反复创建条目或无限自动重试。
