# 完整正文包游戏验收

本文件是验收方案，当前项目没有声称已执行。原占位原型的显示确认不能代替本包验收。本任务不使用Computer Use，以下游戏内操作由用户执行；自动工具负责包文件和来源结构检查。

## 验收包与安装

先在本工程执行构建和预检，使用当前 `dist/release-candidate-20261031-1.0.0-final/location_descriptions_enhanced/` 文件夹。显示名为Descriptions for Every Tile，运行包包含新英文缩略图、隐藏 `.metadata/`、双语本地化、来源、许可及双语玩家说明。英文与简体中文都是首发必测语言，不能只验一种；后续重新构建应填写实际目录与ZIP哈希，不沿用旧记录。

将实际模组文件夹整体复制到EU5用户数据目录的 `mod/` 下，**不要复制整个GitHub工程或ZIP作为工坊内容文件夹**。若目的地已有同名目录，先停止，保留可恢复副本后再由用户决定替换。停用旧占位原型和订阅副本，在游戏“模组和DLC”中启用唯一的一份测试包。只安装模组，不修改Steam原游戏文件。

游戏基线为Steam build 26300913（1.4.6）。验收前可用预检的 `--game-root` 参数核对7份源文件和Steam build；游戏已更新时先重新处理地图/官方保护差异。不要因元数据使用星号就略过版本核对。

## 具体检查

候选地点见 [smoke_samples.json](../workshop/smoke_samples.json)。它包含常规陆地、不可通行陆地、通道、海域、湖泊、较长正文，以及官方保护地点；选择依据是实际ID和数据类别，不冒称已验证游戏内城市等级。

当前共13个样本，最长英文与中文可能对应同一地点，因此按ID去重；样本用途不重复计数，也不代表已测试。

1. 先以英文启动，记录当前游戏build、模组版本、测试包哈希及启用模组列表。
2. 检查至少一个普通陆地点，确认出现真实介绍而非ID占位符；检查另一普通地点、海域与湖泊。无法从界面选择的特殊类别记录“无法检查”及原因，不能直接标通过。
3. 检查最长英文/中文样本：可打开说明、字形可读、引号和换行正常，文本不截断或撑坏界面。若长文本不适配，回到内容工程修订或另行决定UI方案，不自动添加玩法或UI改造。
4. 对照未启用本模组时的官方保护地点，确认官方介绍没有变化。再检查一个没有官方介绍的地点确有新增文字。
5. 切换简体中文、按游戏要求重新加载，重复普通陆地、海域/湖泊及长文本检查，确保不是只显示英文。
6. 查看这次启动后产生的 `error.log`、`game.log` 等相关日志。记录实际文件时间、metadata/localization解析错误和重复键；旧错误与其他模组错误须分清，不能仅凭关键词“没有命中”判定全部正常。
7. 保存并重载测试存档，记录是否正常。成就及联机若未单独测试，继续标为“未验证”；该两项当前不作为对外兼容承诺。

## 真实截图

用Steam内置截图或用户自己的截图工具，至少准备下列三张：

- `english-land.png`：英文界面、普通陆地点的完整介绍。
- `chinese-land.png`：简体中文界面、地点名称和完整介绍可读。
- `water-or-long-text.png`：海域/湖泊介绍或长文本显示。

将审阅后的截图放在 `workshop/screenshots/`，去掉与展示无关的账号/好友信息，保留真实游戏内容。封面插画单独作为封面；不能将它或旧占位截图当作新包游戏效果证明。
